# 跨项目作品画廊 · Throwaway prototype

问题：所有项目的生成结果怎样按图片原始比例汇总浏览，同时保持长列表轻快？

从 `browser-extension/` 运行 `node scripts/gallery-prototype.mjs`，打开：

- http://127.0.0.1:43219/workspace.html?variant=A — 自由瀑布流，按最短列分配图片（建议默认）。
- http://127.0.0.1:43219/workspace.html?variant=B — 项目画册，按项目分组，每组横向展开。
- http://127.0.0.1:43219/workspace.html?variant=C — 聚焦浏览，缩略图列表配大图。

底部箭头或左右键切换方案；输入框、下拉框和预览打开时不拦截方向键。实验台包含 1,200 条重复素材压力数据与中段跳转；默认 36 条示例、10 个模拟项目。搜索、项目/比例筛选、排序、密度、侧栏折叠、预览前后切换、Escape、返回项目示意可交互。所有状态只在内存中，不调用模型，不读写真实项目。实际项目详情仅示意。

复用正式品牌、Icon、SelectField、主题变量和侧栏 CSS；独立 Vite runner 只在本原型服务提供 `/workspace.html`，不修改正式 App、workspace 入口或已有 preview.mjs。原型切换器仅 DEV 显示。

## 素材与性能边界

4 张图片来自公开 `docs/gallery/{urban-poster,watercolor-mug,watercolor-portrait,red-mecha}/result.png`；另 6 张为运行时 SVG 合成示例，不使用私人生成图。原始 PNG 在列表中使用内存 WebP 缩略图，最长边不超过 800px；只有预览和 C 的当前大图读取原图。样例的项目、时间、模式、版本用于交互演示，不代表原始生成记录。

A 根据实际宽高元数据计算卡片尺寸，ResizeObserver 更新列宽，滚动经 requestAnimationFrame 合并。只挂载视口上下各 650px 内的卡片，使用稳定结果 ID；图片预留比例，非首屏懒加载。布局只在数据/容器/密度变化时重算。侧栏或容器尺寸变化按首个相交作品保留浏览锚点。

B 每项目最多先展示 8 张，通过“展开全部”进入 A 完整查看；C 一次展示当前位置附近最多 12 张缩略图。B/C 是结构比较，不代表正式无限滚动实现。
