# QC Alchemy for Chrome

<img src="assets/brand/alchemy.svg" width="72" height="72" alt="QC Alchemy logo" />

将网页中选中的图片交给本机 Codex，通过现有 `alchemy` 技能逆向为提示词。使用 WXT 官方 React + TypeScript 模板、Manifest V3。

**图片悬浮按钮 / 右键菜单 → 本机服务 → Codex App Server → Alchemy → 网页内结果浮层**。

0.1.2 使用 Shadow DOM 直接渲染网页内结果，移除导致内置浏览器浮层空白的扩展 iframe；继续保留普通工具栏弹窗，不依赖原生 `sidePanel`。配对码只保存在扩展后台，浮层通过受限消息读取状态与结果。扩展更新、消息失败与超时会显示明确提示。

更新时先重新加载原扩展目录（ZIP 安装使用最新 ZIP），再刷新 Pinterest 等已打开的网页；现有配对设置沿用。仅更新扩展而不刷新网页，会使旧按钮报 `Extension context invalidated`。

0.1.3 补齐历史图片重新逆向：打开历史记录会恢复本机保存的原图，切换模式后点击「用此图生成完整复刻提示词」或「用此图生成提取风格提示词」，使用同一张图创建新任务，原结果继续保留。界面分别标注当前结果模式和下一次逆向模式。此版本需重启 `npm run bridge`、重新加载扩展，再刷新网页；配对码不变。

0.1.4 新增「主体重演」：主体图 + 原始参考模板 + 已有 Prompt，通过 Alchemy 生成双图重演提示词。更新本机服务、重新加载扩展后刷新网页；配对码和旧历史沿用。

0.1.5 将第三项改为预填的「任务指令」。无需先提取风格；直接使用默认指令，或编辑自己的保留与迁移要求。用户编辑的意图优先于默认模板分工。

0.1.6 统一采用折带字母 A 标志：深橄榄底色、奶油白主形和鼠尾草绿折面。工具栏、页面悬浮按钮、面板页头、空状态、页脚及标签页图标均使用同一源图。

0.1.7 为「提取风格」加入主体图上传和可编辑任务指令：保留图 1 内容与结构，仅迁移图 2 的画法。选中参考图后先打开表单，上传主体后再生成；也可选择「仅提取通用风格」。更新本机服务、重新加载扩展并刷新网页后生效。

## 首次使用

要求：Chrome 116+、Node.js 22.15+（建议当前 LTS）、已安装并登录的 Codex CLI。本机实测版本为 Codex CLI 0.153.4。

```bash
cd browser-extension
npm install
npm run build
npm run bridge
```

1. 保持 bridge 终端运行，复制终端输出的配对码。
2. Chrome 打开 `chrome://extensions`，启用开发者模式，点击「加载已解压的扩展程序」，选择本目录的 `.output/chrome-mv3`。
3. 点击工具栏 QC Alchemy 打开弹窗，在设置中粘贴配对码并连接。
4. 打开或刷新 Pinterest 等网页，将鼠标移到图片上，点击「逆向风格」。也可右键图片选择「用 Alchemy 逆向图片风格」。
5. 网页内浮层显示进度、视觉观察、中英文提示词；支持复制、导出 Markdown、取消任务和查看历史。也可随时从工具栏弹窗查看。

首次默认「提取风格」，选中参考图后上传自己的主体图，再生成风格转换提示词；「完整复刻」直接逆向参考图的具体内容与构图。之后悬浮按钮沿用上次选择的模式。切换模式本身不会自动开始任务，需点击明确标注模式的生成按钮。当前图片与历史图片均支持同图再次逆向，任务执行中可等待或取消后再运行。

## 提取风格

1. 从网页选择风格参考图，或打开历史记录，选择「提取风格」。
2. **图 1：你的主体原图**。上传 PNG、JPEG 或 WebP，默认保留主体身份、内容、姿态、表情、服饰、构图与背景结构。
3. **图 2：风格参考**。自动带入网页所选原图，仅提供配色、光影、笔触、边缘、媒介及材质表现。
4. **输入 3：任务指令**。已填好上述分工，可按自己的意图编辑；不会带入主体重演的旧指令。
5. 点击「生成风格转换提示词」。Codex 实际分析两张图，输出中英文专属提示词，不保留 `[SUBJECT]` 占位符。以后出图时，按 **图 1 主体 → 图 2 风格参考** 的顺序附图。

无需指定主体时，点击「仅提取通用风格」，只分析图 2 并生成带 `[SUBJECT]` 的可迁移配方；该操作不提交已上传的主体图或任务指令。双图转换任务会保存两张图和实际指令，可从历史恢复后更换主体继续使用。仅提取风格默认保留图 1 的结构；主体重演则默认采用图 2 的构图与姿态。

## 主体重演

1. 选择「主体重演」，从网页选一张参考图；也可打开当前或历史记录的原图，无需先完成一次逆向。
2. **图 1：主体图**。上传 PNG、JPEG 或 WebP，提供人物的身份特征或物体的辨识特征；界面显示实际预览。支持更换主体图。
3. **图 2：原始参考模板**。自动带入所选原图，默认提供风格、构图、内容关系、姿态、表情、光影、笔触和材质参考。
4. **输入 3：任务指令**。默认填好「以图 1 为主体，以图 2 为风格参考模板，生成基于图 1 的风格转换与主体重演提示词。」可直接使用，也可按意图改写，例如「保留图 1 的姿势，只迁移图 2 的配色与笔触」。Codex 按编辑后的指令决定保留与迁移内容，不强制套用默认模板分工，也不会自动带入旧逆向结果。
5. 点击「生成主体重演提示词」。输出中英文版本，明确两张图的职责。以后使用此 Prompt 出图时，按 **图 1 主体 → 图 2 模板** 的顺序附图。

此链路生成提示词，不直接生成图片。主体身份随模板的新姿态和视角重新表现；模板类别不适配、关键细节不可见等情况在结果中说明，不能保证精确身份或像素一致。主体图原有的姿势和背景不会默认锁定。

选择「主体重演」后，网页悬浮按钮只收取参考图；任务指令已预填，上传主体图即可提交。指令可编辑，清空时需重新填写。切换模式时保留当前表单输入；未提交的表单关闭后不保存。已提交的重演记录保存两张图与任务指令，可从历史恢复后继续编辑或更换主体再次运行。旧版重演记录沿用其当时提交的 Prompt，作为可编辑的任务输入。仅查看历史不会覆盖当前图片，旧结果不被重写。

关闭浮层或弹窗不影响任务。停止 bridge 或关机将中止当前任务；重启后保留已完成记录，并将中断任务标记为失败。

## 本机 Codex 与技能

- 不集成模型 API、不保存 API Key；通过 `codex app-server` 的 stdio JSON-RPC 调用本机 Codex，沿用其登录和默认模型。本机 Agent 仍可能使用云端模型，并非离线推理。
- 显式发送 `localImage` 和 `skill` 输入。项目真实技能名为 `alchemy`，位于 `../.agents/skills/alchemy/SKILL.md`；QC Alchemy 是扩展产品名。
- Agent 采用只读 sandbox，不自动批准工具操作。输出使用 JSON Schema 约束和本机校验，失败时不会生成假结果。
- 每次逆向创建独立 Codex 会话；未接管当前桌面聊天，也未验证自动在桌面 App 中展示会话。
- 2026-09-29 已在 Codex 内置浏览器的 Pinterest 实测 0.1.2：点击悬浮按钮、读取原图、调用本机 Alchemy、显示真实提示词及读取历史记录均通过。不要求原生扩展侧边栏或扩展 iframe。
- 0.1.3 同日实测：从历史「冷黑湿光与银灰流线」恢复原图，切换到完整复刻并生成「银发黑衣冷调厚涂」。两次输入图片的字节完全一致，新任务模式为 `recreate`，输出保留具体内容且无 `[SUBJECT]` 占位符，原 `style` 结果仍保留。取消、模式切换反馈与历史原图预览也已实测。
- 0.1.4 已通过 TypeScript 与 16 项自动测试；浏览器预览验证主体上传、双图预览、编辑 Prompt、模式切换保留输入和缺失输入禁用提交。本机真实 Codex 双图调用生成「黑发人物的侧身举臂重演」，两张保存图片与提交文件分别一致，输出区分新主体身份与模板姿态、表情、画法，无 `[SUBJECT]` 占位符。重新加载后，又在 Codex 内置浏览器的 Pinterest 浮层实际完成历史双图恢复、上传主体、编辑 Prompt、提交并显示新结果「黑发角色闭眼举臂重演」；确认编辑要求到达服务、参考图字节一致、旧结果保留。
- 0.1.5 已通过 TypeScript、打包与 17 项自动测试。浏览器预览验证新图默认指令、上传后可提交、编辑后切换模式保留输入、清空禁用，以及旧风格结果不会自动覆盖任务指令。真实本机 Codex 对同一组双图分别生成「黑发人物侧身重演」和「正面原构图的低饱和绘画迁移」：前者按默认指令采用模板姿态，后者按自定义指令保留主体正面站姿、睁眼、白色高领衣服与原背景，仅迁移画法。新版扩展在 Pinterest 的验收需重新加载后进行。
- 0.1.7 已通过 TypeScript、打包与 20 项自动测试。浏览器预览验证提取风格的主体上传、默认与自定义指令、切换模式保留草稿、清空指令禁用双图生成，以及通用提取入口独立可用。真实本机 Codex 双图风格任务生成「原构图冷灰绘画风格迁移」，保留主体原图的站姿、表情、衣服和背景结构，仅迁移参考图的配色与分区域画法；两张原图及指令能完整恢复，输出无 `[SUBJECT]`。重新加载 0.1.7 后，又在 Pinterest 实际完成悬浮选图、历史双图恢复、主体上传、编辑指令、提交及结果显示，生成「保留睁眼双手动作的灰调绘画迁移」；后台确认两张图片字节与原文件一致，编辑后的完整指令已传入。

可自定义本地路径：

```bash
CODEX_BIN=/absolute/path/to/codex \
ALCHEMY_SKILL_PATH=/absolute/path/to/alchemy/SKILL.md \
npm run bridge
```

需保留技能的 `references/` 等伴随文件。启动前可用 `codex --version`、`codex login status` 检查 CLI；CLI 不在 PATH 时设置 `CODEX_BIN`。

## 图片与数据

- 悬浮检测在网页内执行，**点击前不上传图片**。只发送选择的图片、模式和去除查询参数的来源 URL；双图风格转换与主体重演还发送用户上传的主体图和任务指令。网页正文、cookie、登录数据不会交给 bridge。
- 优先读取当前图片资源，不携带网页 cookie；支持 `<img>` / `<picture>` 当前资源和单层 CSS 背景图。最长边限制为 2560 像素，优先 PNG；较大图转 JPEG。
- 原图无法读取时，悬浮入口尝试截取所选图片的可见区域，标记「屏幕截取」。不会将整个网页截图交给模型。图片需完整可见；页面变动或切换标签时拒绝截取。
- 主体上传原文件最大 20 MB，浏览器实际解码后将最长边限制为 2560 像素，保存体积最多 2 MB；参考图保存最多 4 MB，避免双图超过扩展 storage 配额。任务指令最多 20000 字符。点击生成前，主体图只在表单中读取与预览。
- 跨域 iframe、canvas、浏览器内部页、Chrome Web Store 页面，以及被遮挡或未加载的图片不保证支持。右键入口下载失败时需改用悬浮入口。
- 为支持任意网站与截图，扩展请求 `<all_urls>`；不会自动批量发送网页图片。
- bridge 仅监听 `127.0.0.1:43187`，请求需配对令牌，并校验 Host 和浏览器 Origin。令牌仅用于本机配对。
- 令牌、选中图片、历史结果位于 `.local/`（已忽略提交）；扩展 storage 仅保留当前图片与连接设置。模型处理遵循你的 Codex 账户配置。
- 同时只处理一个任务。历史界面展示最近 30 条。停止服务后可手动删除 `.local/` 清空记录；删除 token 后需重新配对。

## 开发与验证

品牌源图为 `assets/brand/alchemy.svg`。界面内嵌该 SVG，避免扩展资源地址在网页浮层中不可用；`npm run icons` 从同一源图生成 `public/icon/` 中的 16/32/48/96/128 px 图标。`build` 与 `zip` 会先更新图标。

Git 仅保存 `browser-extension/` 与根目录忽略规则。本地 `.local/`（配对令牌、Prompt JSON、参考图、截图）、下载/实验目录、依赖与构建产物不提交，也不会被删除；必要的品牌 SVG/PNG 和项目配置 JSON 正常提交。`alchemy` 技能是外部前置依赖，需在本机安装并通过上面的 `ALCHEMY_SKILL_PATH` 指定；当前工作区已有技能不包含在此次 Git 快照中。

```bash
npm run dev       # WXT 开发模式
npm run compile   # TypeScript 检查
npm test          # 先 build；验证 bridge、任务状态与扩展兼容性
npm run build     # .output/chrome-mv3
npm run zip       # 扩展 ZIP，不包含本机 bridge / skill
npm run preview   # 弹窗视觉预览，不调用 Codex
```

预览地址 `http://127.0.0.1:43188/?state=result`，也支持 `empty`、`running`、`failed`、`reenact`、`style-new`、`reenact-new`（尚未逆向的参考图），均使用明确标记的示例数据。主体图上传和指令编辑使用真实表单；预览的提交按钮不调用 Codex。预览不能替代真实扩展中的权限、悬浮和跨域图片验收。

`/content-preview` 用于网页内浮层验收，`?state=invalidated` 可模拟扩展失效提示；同样只使用示例数据。

人工验收：重新加载扩展并刷新网页 → 连接 bridge → 悬浮图片 → 正确参考图和任务进度 → 复制提示词 → 测试取消、连续选择、浮层关闭与工具栏重开，以及关闭 bridge 后的连接错误。
