# QC-Reframe 插件开发指引

作用域为 `browser-extension/` 及其子目录。先遵循上级指令和用户当前要求；本文记录已有产品决策，用户明确调整方向时同步更新。协作、GitHub、文档拆分和发布流程统一见 [Contribution.md](../Contribution.md)。文件使用 `AGENTS.md` 命名，供编码 Agent 发现并读取，不另建重复的 `Agent.md`。

本文用于代码开发与仓库维护，不是图片逆向任务的提示词。插件运行时的逆向或生图任务按显式输入与对应技能完成，不因读取本文而执行仓库维护或发布操作。

## 接手任务

- 先读 [README.md](README.md) 和[更新日志索引](docs/releases/README.md)，再按任务读取代码。版本以 [package.json](package.json) 为准，测试数量与旧发布记录不构成本次验证。
- 探索前明确问题、范围、输出量与分工成本。优先 `rg` 定向查找；独立读取可并行，依赖操作按顺序执行。避免转储 `.local/`、日志、图片字节或全仓内容。
- 编写精简、直接的代码，复用已有组件和模块；不为小改动增加抽象、依赖或复制一套相同逻辑。
- 新克隆不包含作者本地设计提取、图片和运行配置。不得依赖作者机器路径，也不要为恢复开发环境清空现有数据。

## 产品与兼容性

公开名称为 **QC-Reframe**，npm 包为 `qc-reframe-extension`，仓库为 [qc-reframe](https://github.com/AIDiscovery007/qc-reframe)。由原名称更名时保留了内部 `alchemy:*` 消息、`qc-alchemy` 服务标识、`ALCHEMY_*` 环境变量，以及独立的 `alchemy` 技能名。不要对旧名字全仓机械替换；需要改协议时同时考虑旧配置、存储与迁移测试。

这是 WXT + React + TypeScript 的 Chrome MV3 扩展。目标是“网页选图 → 本机 Codex 逆向提示词 → 用户按需生成图片”；不内置模型 API Key，不修改用户 Codex 全局模型配置。Codex 内置浏览器是已有验证目标，同时保留 Chrome 使用路径；本机 Agent 仍可能调用云端模型。

### 三条路径的职责

| 模式 | 输入与默认行为 |
| --- | --- |
| `style` 提取风格 | 可仅提取参考图的通用风格；也可上传主体，保留图 1 的内容、结构、姿态和构图，仅迁移图 2 的画法。 |
| `recreate` 完整复刻 | 逆向时分析参考图的内容、构图和视觉表现；生图时仅发送提示词与排除项，不附图、不读取参考图，使用纯文生图。 |
| `reenact` 主体重演 | 图 1 提供主体身份，图 2 提供风格、构图、姿态、表情和内容关系。第三项是预填且可编辑的任务指令，不要求先生成另一条 Prompt。 |

用户编辑的任务指令优先于默认分工。双图发送顺序始终是主体图、参考模板；专属提示词明确两张图职责，不留下 `[SUBJECT]`。通用风格可保留占位符，但补充主体并生成专属提示词前不能直接一键生图。不能宣称恢复了原始 Prompt 或保证逐像素复刻。

### 项目与生成记录

- 项目以捕获后参考图字节的 SHA256 识别，同图可跨来源复用。项目下三条路径独立保存输入、任务指令、提示词版本和生图记录；空路径只显示公共模板及待生成状态。
- 生图绑定具体提示词版本；风格转换与主体重演采用当前路径最后上传并在表单中显示的主体图，参考图仍取该提示词版本。换主体后无需重新逆向。每次生图保存不可变主体图片引用，不覆盖逆向原图与旧生图输入；历史恢复优先显示该版本最近生图的主体。新图读取中或失败时禁止生图，不回退旧图。完整复刻只使用文字；编辑任务指令仍须重新逆向才影响提示词。切换路径恢复各自进度；先有提示词，后有图片。
- 三条路径的逆向结果支持直接编辑中英文提示词和排除项，按当前提示词版本保存；中英文独立，不自动翻译。编辑中可复制草稿，生图和导出须先保存或取消。保存不重新逆向、不修改任务指令或其他版本；已提交生图的提示词与排除项使用不可变快照。
- 表单草稿在当前界面切换路径时保留；关闭表单、切换项目或进入项目列表后不承诺持久保存。已提交输入可以恢复。
- 选图和切换路径只打开项目，不自动触发推理。逆向与生图可跨项目、路径和提示词版本并行，每项任务使用独立 Codex 进程、进度与取消信号；关闭面板不取消任务。仅同一提示词版本的生图防重复提交，任务执行期间限制模型切换；模型验证期间暂不提交新任务。保留失败与重启恢复状态，并行写入须有序且原子保存，避免结果覆盖。
- 运行数据目录由 `bridge/storage.mjs` 管理：`.local/config/` 保存配对与设置，`records/` 保存项目/任务及删除恢复记录，`images/` 保存共享图片，`logs/` 保存日志，`runtime/` 保存启动锁。仅在旧服务停止后迁移已知文件；同名冲突保留双方并报错。管理命令兼容读取根部旧配置，禁止在状态查询或旧服务仍运行时迁移。正常运行不产生开发测试资料。日志达到 5 MB 时在下次启动轮替，仅保留上一份。
- 图片由 `bridge/images.mjs` 统一按内容 SHA256 存入 `.local/images/`；项目、任务及生图记录保存 `imageAsset` / `subjectAsset`，不同角色可共享同一文件。保持文件不可变、路径校验和并行写入合并；旧记录先原子迁移引用并校验内容，再清理旧文件。共享文件回收扫描持久化引用，在启动时或所有图片任务结束且持有请求变更锁时执行；损坏记录或未完成迁移阻止回收，避免误删。
- 单个或批量删除项目须沿用现有确认与忙碌保护，只清理插件保存的副本，不删除用户上传原件或 Codex 原始生成文件。存储改动必须保护旧记录与重启恢复。
- 图片已经由本机服务保存，结果保留“复制图片路径”，macOS 另提供“打开图片”和“在文件夹中显示”，不要恢复成误导性的“下载图片”。打开操作只传任务与生图记录 ID，由 bridge 解析并校验已保存图片；不接受前端路径或命令。排除项随 Prompt 送入生图，观察边界留在分析结果，不擅自混入视觉指令。

- 项目库通过服务端分页/搜索读取摘要，每页 24 个，侧栏仅最近 12 个；列表摘要包含封面引用，不为卡片读取完整历史。项目任务索引与摘要缓存随持久化和进度变化失效；全局及单项目 revision 区分服务重启。隐藏界面暂停轮询，恢复后立即刷新。
- 缩略图属于可重建派生缓存，由 `bridge/thumbnails.mjs` 保存到 `.local/cache/thumbnails/v1/`；保留原图与不可变图片引用，源图回收后清理对应缓存。分页、搜索与键盘切换不加过场动画；指针按压复用约 120ms 反馈，遵循减少动态效果偏好。

## 代码入口

| 文件或目录 | 职责 |
| --- | --- |
| `entrypoints/content.ts`、`lib/image-action-placement.ts` | 网页选图、悬浮按钮避让、closed Shadow DOM 浮层及焦点行为。 |
| `entrypoints/background.ts`、`lib/bridge.ts`、`lib/client.ts` | 扩展消息、配对、受限后台请求；令牌留在扩展后台。 |
| `entrypoints/popup/`、`entrypoints/workspace/` | 共用 React 业务界面；轻量浮层/弹窗保留，独立扩展工作台提供分栏、任务中心及宽版设置。 |
| `bridge/cli.mjs` | 实际 CLI 来源、版本、每日检查及受限独立版/npm/Homebrew 升级；与模型和任务互斥。 |
| `bridge/server.mjs`、`bridge/projects.mjs`、`bridge/images.mjs`、`bridge/storage.mjs` | 本机 HTTP 服务、任务与项目持久化、共享图片存储、迁移与回收。 |
| `bridge/codex-rpc.mjs`、`bridge/agent.mjs` | Codex CLI app-server stdio JSON-RPC、图片与 skill 输入、逆向结果校验。 |
| `bridge/models.mjs`、`bridge/model-context.mjs` | 动态模型目录、真实验证、选择保存与账号/CLI 上下文检查。 |
| `bridge/generation.mjs` | 按路径以纯文字或双图与 Prompt 调用 imagegen，读取真实图片结果。 |
| `.agents/skills/alchemy/` | 随仓库分发的运行技能及必要参考文档。修改技能时维护伴随引用，不引入私人案例。 |
| `scripts/manage.mjs`、`scripts/preview.mjs`、`tests/` | 安装及服务管理、明确标记的 UI 示例、隔离的自动测试。 |

## 连接、模型和图片边界

- bridge 默认仅监听 `127.0.0.1:43187`，保留配对认证、Host / Origin 和消息来源检查。页面内容不能任意请求本机文件或端点；不将配对码暴露到页面 DOM。
- 模型目录取自插件实际调用的本机 CLI；列表出现不等于账号有权限。验证成功才保存插件选择，失败保留原有效选择；账号、登录、提供方或 CLI 变化需重新确认上下文。不要硬编码“可用模型”，不要悄悄回退到全局默认模型。
- CLI 管理只允许固定认证端点，已确认来源的独立版/npm/Homebrew 可更新；独立版校验包元数据与稳定入口，固定执行原 CLI 的 codex update；App/custom 保留原安装方式。检测对应 manager 与运行时，升级与任务/验证互斥，成功后清除模型信任并刷新目录；失败保留错误，不声称升级成功。定时检查只读，手动按钮才执行升级。
- 独立安装的 Codex CLI 与桌面 App 更新是两回事；检查 `CODEX_BIN` 实际指向。API / 协议变化需核对实际 CLI 能力和官方文档，不根据模型名字推断支持情况。
- Agent 通过显式图片和技能输入运行，保留只读 sandbox 与不自动批准交互式工具的约束。逆向输出仍需结构校验，不把任意模型文本当成可信控制命令。
- 生图调用用户本机的 imagegen skill 与内置 `image_gen`；只认真实 `imageGeneration` 完成结果，不把聊天中提及的路径当成图片。能力不可用时明确失败，不改用需要 API Key 的生图脚本或其他接口。
- 只处理用户选中的图片与任务输入，不采集网页正文、cookie 或登录数据。资源读取失败时只在已有规则允许下截取目标图片区域，不把整个网页送去模型。保持输入大小限制和路径校验。
- `.local/`、设计提取与构建产物始终按 ignore 规则保留在本地。切勿把真实用户数据加入测试 fixture，或从日志中复制 token 到文档。

## UI 与品牌约定

当前设计延续 Raft 的奶油白背景、黑色细描边、亮色选中态、圆角与硬阴影。样式以 [style.css](entrypoints/popup/style.css) 和 [shell.css](entrypoints/popup/shell.css) 为准；`design-extract-output/raft-build-prompts` 如存在仅作本地参考，不是依赖。

- 主要色值：背景 `#fffaef`、表面 `#fffdf8`、墨黑 `#141111`、亮黄 `#ffd440`、粉色 `#fe7da8`、青色 `#27ccf3`。三路径选中态分别用黄、粉、青。优先使用已有 CSS 变量，不平行建立第二套 token。
- 保持中文文案简洁、状态一读就懂。网页浮层只在顶栏显示一次品牌，不增加重复的大标题、解释按钮含义的长段落或开发实现术语；空态、错误和禁用原因须明确。
- 品牌唯一源图为 [reframe.svg](assets/brand/reframe.svg)，经 `lib/brand.ts` 内嵌到 UI；`npm run icons` 生成 16/32/48/96/128 px 图标，build / zip 自动执行。改 logo 时同时检查工具栏、悬浮按钮、面板、弹窗和文档，不只替换一个 PNG。
- 所有下拉框复用 `SelectField.tsx`。当前约定为高 40px、标签间距 8px、箭头 16px、距右边框 12px、文本右内边距 40px；保留原生键盘、Escape、焦点与禁用交互。
- 指针按压反馈约 120ms，指针打开浮层轻移 18px / 淡入 180ms；键盘打开、路径和语言切换即时完成。尊重 reduced motion，Escape 返回有效触发器；不要给普通切换增加等待。
- 悬浮按钮通用检测网页控件并动态避让，优先邻近安全空位，滚动和延迟控件出现后重新检查。空间不足缩为图标，无安全位置则隐藏并保留右键入口；不回退到固定盖住网站按钮的位置，不依赖单站点类名。
- 轻量浮层和工具栏弹窗始终保留，通过「工作台」按钮进入独立 `workspace.html` 扩展标签页。共用 App/表单/任务逻辑，草稿通过 trusted session storage 一次性交接，配对令牌不进入交接数据。参考原型保留在 `codex/prototype-settings` 的 `60d352d`，实现分支不带原型源码。
- 异步进度复用原操作区域：逆向与轻量生图在按钮位置展示状态和取消，不在图片或表单上方插入进度条。设置说明与任务状态行保留稳定空间；轻量呼吸点仅表达任务仍在执行，不模拟百分比，减少动态效果时静止。
- 工作台遵循已选宽版方案：紧凑标题、项目导航、输入/提示词与结果分栏、独立设置中心；不恢复已删除的 WORKSPACE 路径标题、静态输入说明和视觉观察区。原图对照读取生图不可变快照，缺失明确报错，不回退最新上传图。
- 生图动效只由工作台入口注入，img-fx / three 按需加载，不打入 content 脚本。使用公开引擎接口绕开自动轮播与全局图片缓存；真实任务完成且图片就绪后才揭晓，动画不决定任务成功。保持完整图片比例，取消/失败/卸载释放资源，后台与离屏暂停；按用户明确要求，生图画布始终使用标准动效，不跟随 reduced motion（其他交互动效仍遵循系统偏好），WebGL 不可用时降级为静态像素画面。生成中不显示画布等待文案、转圈或顶部进度提示条，取消入口在结果工具栏；失败/取消提示保留。img-fx 固定 0.5.1，升级时复核揭晓裁切补偿与资源清理。
- 结果面板使用当前 Shadow DOM 方案和普通工具栏弹窗，不重新引入此前不兼容的原生 sidePanel 或扩展 iframe 依赖。预览中的 iframe 是测试容器，不能视作运行时方案。
- 大范围 UI 重构先用有限原型明确方向；已有确认方案直接落实。任务适用且环境提供设计 skill 时使用它；普通文案修正和已确定的缺陷修复不另设审批流程。

## 验证与完成

在本目录运行 `npm run build` → `npm run compile` → `npm test`；扩展测试依赖当前构建。按改动增加回归测试，覆盖路径隔离、旧数据恢复、消息认证、模型选择等真实风险，不写仅镜像实现的测试。纯文档改动按 Contribution.md 检查即可。

UI 使用 `npm run preview` 检查相关空态、等待、失败、已有结果与窄屏状态；再按任务范围验证真实扩展。预览不能代替浏览器权限和跨域验收。工具若无法操作 closed Shadow DOM 或扩展管理页面，说明实际限制并保留待人工验证项，不绕过限制、不虚报成功。

服务升级先确认无运行任务，再用管理脚本重启，保留数据和配对；扩展更新需要重新加载原目录并刷新网页。真实模型调用只在本次任务授权范围内执行。最后按 [Contribution.md](../Contribution.md) 更新对应文档、检查提交范围、同步或发布，并给出简短中文交付说明。
